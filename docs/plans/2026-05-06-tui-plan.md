# Plan: Terminal UI untuk `lm-router`

## Summary
- Tambahkan command baru `lm-router tui` untuk membuka fullscreen Terminal UI seperti 9Router.
- TUI menjalankan server proxy embedded dalam proses yang sama, dengan kontrol start/stop/restart dari UI.
- TUI mengelola provider OpenAI Codex OAuth, API keys, server settings, Codex CLI config helper, dan live logs.
- Command lama tetap ada: `serve`, `auth`, `keys`, `codex` tidak dihapus.

## Key Changes
- Gunakan Charm stack: `bubbletea`, `bubbles`, `lipgloss`.
- Tambah package `internal/tui` untuk screen/state/navigation dan `internal/app` untuk shared service layer antara CLI command lama dan TUI.
- Tambah server controller embedded:
  - Start/stop/restart server dari TUI.
  - Default endpoint tampil sebagai `http://localhost:19090/v1`.
  - Status server: `OFF`, `STARTING`, `ON`, `ERROR`.
  - Bind host/port bisa diedit dari Settings.
- Tambah persistent settings di SQLite:
  - `host`, `port`, `log_requests`, `log_upstream`, `log_body_limit`, `default_model`.
  - Default: `127.0.0.1`, `19090`, request/upstream logging ON, body limit 64KB, model `gpt-5.3-codex`.
- Refactor logging agar cocok dengan TUI:
  - Proxy dan upstream Codex logging tidak langsung merusak layar TUI.
  - Log masuk ke ring buffer in-memory dan optional stdout untuk command `serve`.
  - TUI punya screen `Logs` untuk request masuk dan upstream request/response.
  - `Authorization` tetap redacted.

## TUI Screens
- Home:
  - Header `LM Router Terminal UI`.
  - Tampilkan endpoint, server status, active provider count, API key prefix.
  - Menu: `Providers`, `API Keys`, `Server`, `Settings`, `Logs`, `Codex Config`, `Quit`.
- Providers:
  - List provider group `OpenAI Codex (OAuth)`.
  - Tampilkan alias `cx`, model list ringkas, connection count.
  - Actions: `Add New Connection`, buka detail connection, back.
- Add Provider:
  - Generate OAuth URL seperti command `auth add`.
  - Tampilkan URL untuk dicopy manual.
  - Input callback URL pakai TUI text input yang support cursor kiri/kanan.
  - Exchange token, save account, optional auto-test.
  - Success message sederhana; error tampil human-readable.
- Provider Detail:
  - Tampilkan name/email, provider, status, priority, expiry, cooldown/needs reauth.
  - Actions: `Rename`, `Test Connection`, `Refresh Token`, `Enable/Disable`, `Delete`.
- API Keys:
  - List key name, id, prefix, created date.
  - Actions: `Create Key`, `Delete Key`.
  - Secret penuh hanya ditampilkan sekali setelah create.
- Server:
  - Start/stop/restart embedded proxy.
  - Tampilkan current endpoint dan bind address.
  - Tampilkan active server error kalau gagal bind port.
- Settings:
  - Edit host, port, default model, logging toggles, body log limit.
  - Save ke SQLite.
  - Kalau server sedang ON dan host/port berubah, UI minta restart server.
- Logs:
  - Live request log dan upstream log.
  - Filter sederhana: `All`, `Proxy`, `OpenAI`.
  - Clear in-memory log.
- Codex Config:
  - Generate config text seperti `codex print-config`.
  - Tampilkan `~/.codex/config.toml` dan `~/.codex/auth.json` content.
  - Tidak menulis file otomatis pada versi ini.

## Interface / Behavior
- New command:
  - `go run ./cmd/lm-router tui`
  - Optional flags: `--data-dir`, `--host`, `--port`.
- Existing command behavior tetap kompatibel.
- TUI uses same SQLite default store: `~/.lm-router/lm-router.db`.
- TUI uses same OAuth/manual callback flow already implemented.
- TUI uses same server/proxy logic as `serve`, not duplicate implementation.
- Keyboard:
  - `Up/Down` move selection.
  - `Enter` activate.
  - `Esc` or `Backspace` back.
  - `q` quit on root/home.
  - Text inputs support left/right, backspace, delete, paste.
- Not in this phase:
  - No web frontend.
  - No tunnel/cloudflare.
  - No combos/multi-provider strategy UI until provider routing expands beyond OpenAI Codex.

## Test Plan
- Unit tests:
  - TUI navigation state: menu movement, back stack, selected item.
  - Settings persistence and defaults.
  - Server controller start/stop/restart behavior with test handler.
  - Provider actions call existing store/OAuth/test service correctly.
  - API key create/list/delete service output hides full secret except create result.
  - Logger ring buffer stores proxy/upstream events and redacts `Authorization`.
- Integration tests:
  - Start embedded server from controller, call `/health`, stop server, verify port closes.
  - TUI provider test action against fake Codex upstream.
  - TUI API key create then `/v1/models` with generated key.
- Manual verification:
  - `go test ./...`
  - `go build ./cmd/lm-router`
  - `go run ./cmd/lm-router tui`
  - Add provider flow with manual callback.
  - Start server from TUI, call OpenAI SDK/curl through proxy.
  - Confirm logs appear in Logs screen and terminal UI remains stable.

## Assumptions
- TUI style follows the screenshots: dark terminal, orange title separators, star menu cursor, breadcrumb text.
- `lm-router tui` is the only new entrypoint; running `lm-router` without args still prints usage.
- Embedded server is local-first; default host remains `127.0.0.1`, user can change to `0.0.0.0`.
- API key secrets are not recoverable after creation because store only keeps hashes.
- Codex Config is print-only; TUI must not write automatically to `~/.codex/config.toml` or `~/.codex/auth.json`.
